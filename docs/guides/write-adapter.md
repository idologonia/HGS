# Як підключити сервер іншою мовою або написати власний адаптер

Є два шляхи — від простого до складного. Ядро HGS змінювати не потрібно в жодному з них.

## 1. Адаптер `process` + Worker Protocol (будь-яка мова)

Ваша програма (Node.js, Go, C#, Rust, …) підключається до HGS через локальний WebSocket і отримує події
гравців. Вхід, кімнати, ліміти й безпеку бере на себе HGS.

`hgs-game.json`:

```json
{
  "id": "my-go-game", "name": "My Go Game", "adapter": "process",
  "backend": { "mode": "worker", "command": "bin/server.exe", "args": ["--data", "{data_dir}"] },
  "auth": { "mode": "invite" }
}
```

* `command` — програма в папці гри (`bin/server.exe`) або ім'я з PATH (`node`). Програми поза папкою гри
  HGS запускає лише після вашого дозволу (з'явиться запит у GUI).
* Плейсхолдери в `args`: `{port}`, `{data_dir}`, `{game_id}`, `{game_dir}`.
* Змінні середовища для програми: `HGS_WORKER_URL`, `HGS_WORKER_TOKEN`, `HGS_GAME_ID`, `HGS_DATA_DIR`.

Протокол — [06-protocol.md §6.4](../architecture/06-protocol.md). Мінімум, який має реалізувати програма:

1. Підключитися до `HGS_WORKER_URL`, надіслати `w.hello {token, game_id, api: 1}`.
2. Відповісти на `w.welcome` повідомленням `w.reply {ready: true}` (поле `re` = `id` запиту).
3. Відповідати на `w.ping` (`w.reply {}`), на `w.player.join` (`{accept: true}`), на `w.save` (`{supported: false}`
   або дані).
4. Обробляти `w.player.event` і надсилати гравцям `w.send {room_id, e, d, to?, except?}`.
5. На `w.shutdown` — зберегтися і завершитися; якщо з'єднання з HGS закрилося — завершитися.

Готовий приклад на ~30 рядків: [examples/node-worker/worker.js](../../examples/node-worker/worker.js).

## 2. Адаптер `process`/`python` у режимі `standalone` (наявний сервер)

Якщо у гри вже є свій сервер зі своїм протоколом, HGS керує процесом (запуск, зупинка, логи, ресурси, падіння),
дає йому вільний порт (`{port}` в аргументах і змінна `PORT`) і пропускає до нього гравців через
`wss://<адреса HGS>/hgs/v1/proxy/<game_id>/…` — той самий тунель, що й для інших ігор. Сервер має слухати
лише `127.0.0.1`. HGS застосовує ліміти розміру й частоти повідомлень, перелік дозволених Origin і, якщо
`backend.proxy.require_login = true`, вимагає вхід HGS першим повідомленням (`hello`, як у SDK).

Обмеження: правила гри і її власний вхід лишаються на боці гри; Windows не дає «м'якої» зупинки чужому процесу,
тому при Stop сервер буде завершено — зберігайте стан самі (у `{data_dir}`).

## 3. Новий тип адаптера на Python (для розробників HGS)

Коли потрібна інша поведінка запуску (наприклад, Java-сервер з RCON), напишіть клас на основі
`hgs.adapters.base.BaseAdapter` (контракт — [03-adapters.md](../architecture/03-adapters.md)) і зареєструйте
його в `hgs/adapters/registry.py`. Адаптер отримує `AdapterContext`, обмежений своєю грою, і не має доступу
до інших ігор. Готові «цеглинки»: `WorkerBackend` (процес + Worker Protocol) і `StandaloneBackend`
(процес + проксі). Сумісність: ядро перевіряє `api_version` адаптера.

Завантаження сторонніх адаптерів-плагінів без зміни коду HGS поки не реалізоване — для інших мов
використовуйте шлях 1 або 2.

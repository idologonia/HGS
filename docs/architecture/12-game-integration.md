# 12. Підключення ігор до HGS

## 12.1. Нова гра (створена з Claude з нуля)

1. У запиті до Claude додати: «Гра повинна використовувати HGS: підключити `hgs.js`, адресу сервера брати
   через `HGS.fromUrlParams()`, додати `hgs-game.json`». Шаблон промпту буде в `docs/guides/add-new-game.md`.
2. Обрати режим:
   * `relay` — клієнтська логіка, найпростіше, підходить для кооперативу/казуальних ігор;
   * `logic` — серверна логіка в `server/logic.py` (рекомендовано для змагальних ігор).
3. Опублікувати клієнт на GitHub Pages, клонувати репозиторій на ПК.
4. HGS → Games → «Додати гру» → вибрати директорію → Start → Invite → надіслати посилання друзям.

## 12.2. Наявна гра — обов'язковий процес (розділ 14 ТЗ)

Інтеграція завжди виконується в такому порядку. Код гри не змінюється до погодження плану.

| Крок | Що робиться | Результат |
|------|-------------|-----------|
| 1. Аналіз архітектури | Структура файлів, ігровий цикл, де живе стан, як рендериться, збереження | Короткий опис гри |
| 2. Поточний онлайн | Немає / localStorage / WebRTC / Firebase / власний WS / hot-seat | Опис мережевої частини |
| 3. Проблеми синхронізації | Хто авторитетний, гонки, недетермінізм (`Math.random`, `Date.now`), залежність від FPS, дублювання подій | Список ризиків |
| 4. Що має бути на сервері | Мінімальний набір (наприклад, лише лобі і пересилання дій) або авторитетна логіка — з поясненням компромісів | Рекомендація relay vs logic |
| 5. Зміни для сумісності | Тонкий мережевий шар-обгортка навколо наявних функцій гри | Опис змін |
| 6. План адаптації | Покроковий план із оцінкою ризиків | Документ `HGS_INTEGRATION_PLAN.md` у репозиторії гри |
| 7. Перелік файлів | Які файли змінюються/додаються і чому | Таблиця |
| 8. Погодження | **Чекаю вашої відповіді**, якщо зачіпаються механіки або структура гри | — |
| 9. Реалізація | Лише погоджені зміни, окремою гілкою, з описом у коміті | PR/гілка |

### Заборонено без вашого дозволу

Змінювати механіки, баланс, прогресію, дизайн; видаляти функції; переписувати гру з нуля; змінювати формат
збережень без необхідності; замінювати наявні системи новими заради зручності.

### Типова мінімальна інтеграція

* Додається `hgs.js` (окремий файл) і `net/hgs-bridge.js` — модуль, який перекладає ігрові дії гри у
  `HGS.send(...)` і вхідні події в наявні функції гри.
* У наявних файлах — мінімальні точки підключення (виклик bridge при старті, при дії гравця).
* Додається `hgs-game.json` і, якщо потрібно, `server/logic.py`.
* Одиночний (офлайн) режим гри лишається працездатним — HGS вмикається лише якщо в URL є `?hgs=`.

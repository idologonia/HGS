# 08. Графічний інтерфейс

## 8.1. Принципи

* PySide6 Qt Widgets, темна тема через QSS (власна палітра, без сторонніх тем).
* GUI — **тонкий клієнт** ядра: усі дії йдуть через Admin API, стан приходить потоком подій. GUI не тримає
  власної копії «істини» і ніколи не виконує мережеву/файлову роботу в головному потоці.
* Кожна кнопка або виконує реальну дію, або неактивна з поясненням у підказці (наприклад, «Запустіть сервер»).
  Ніяких «заглушок».
* Помилки показуються явно: банер на сторінці + запис у Logs.
* Якщо ядро впало/не відповідає — верхній червоний банер «Ядро зупинено» з кнопкою «Перезапустити ядро»
  і посиланням на лог.

## 8.2. Каркас вікна

```
┌──────────────────────────────────────────────────────────────────────────┐
│ HOME GAME SERVER                          ● Core: Running   🌐 Tunnel: ON │
├────────────┬─────────────────────────────────────────────────────────────┤
│ ▣ Dashboard│                                                             │
│ ▣ Games    │                    Вміст поточної вкладки                   │
│ ▣ Players  │                                                             │
│ ▣ Rooms    │                                                             │
│ ▣ Network  │                                                             │
│ ▣ Logs     │                                                             │
│ ▣ Settings │                                                             │
├────────────┴─────────────────────────────────────────────────────────────┤
│ 2 сервери працюють · 5 гравців онлайн · CPU 12% · RAM 41%                 │
└──────────────────────────────────────────────────────────────────────────┘
```

Іконка в системному треї: закриття вікна згортає в трей, якщо працюють сервери (налаштовується).
Вихід із трею з активними серверами → діалог підтвердження.

## 8.3. Вкладки

### Dashboard
Картки-показники: стан ядра, активні сервери (x/y), гравці онлайн, CPU, RAM, мережа (↓/↑ КБ/с, міні-графік
60 с), стан тунелю + зовнішня адреса з кнопкою «Копіювати». Нижче — стрічка останніх подій (старт/стоп,
входи гравців, попередження безпеки) з фільтром.

### Games
Сітка карток ігор:

```
┌─────────────────────────────────┐
│ Tank Arena            ● RUNNING │
│ html · logic · v1.4.2           │
│ 👥 3 гравці · 🚪 1 кімната       │
│ CPU 4% · RAM 82 МБ · 00:42:10   │
│ [Start] [Stop] [Restart]        │
│ [Settings] [Logs] [Players]     │
│ [Status] [Invite] [Saves]       │
└─────────────────────────────────┘
```

* `+ Додати гру` → майстер: вибір директорії гри → читання `hgs-game.json` (або форма створення маніфесту) →
  валідація з показом помилок → підтвердження allowlist (інтерпретатор/директорія) → збереження.
* `Видалити з реєстру` → гра зникає з HGS; файли гри не видаляються; дані HGS (збереження) — за окремим
  прапорцем.
* **Stop/Restart при активних гравцях** → діалог: «На сервері 3 гравці. Їх буде відключено через N секунд,
  стан буде збережено. Продовжити?» з полем grace-періоду.
* Settings — форма, згенерована з JSON-схеми адаптера; зміни валідуються ядром до збереження; якщо гра
  працює — «Зміни набудуть чинності після перезапуску».
* Status — детальна панель: стан, PID, uptime, останні помилки, кількість перезапусків, метрики гри
  (`w.status`), можливості адаптера.
* Invite — створення коду/посилання запрошення (термін, кількість використань, кімната), QR-код,
  кнопка «Копіювати посилання».

### Players
Таблиця: гра, ім'я, ID, статус (онлайн/офлайн), кімната, IP (маскований за замовчуванням), остання
активність. Дії: Kick (з причиною), Ban/Unban, відкликати токени. Фільтр за грою.

### Rooms
Таблиця кімнат з групуванням за грою: назва, ID, гравці (x/max), статус, хост, вік. Дії: створити,
змінити ліміт/параметри, заблокувати вхід, закрити (з підтвердженням, якщо є гравці), переглянути
гравців.

### Network
Режим (Local / LAN / Direct / Tunnel), порт, стан тунелю з кнопками Start/Stop, публічна адреса, публічна IP,
індикатор CGNAT, кнопка «Перевірити доступність» з результатом і поясненням, налаштування Direct (домен,
сертифікат, DuckDNS), завантаження/шлях `cloudflared`, список обмежень обраного провайдера.

### Logs
Вибір джерела (Core, Security, гра X — server/stdout/stderr), фільтр рівня, пошук, автопрокрутка, пауза,
«Відкрити папку логів», «Експорт». Показ — віртуалізований список (ефективно для великих логів).

### Settings
Назва сервера, порти, мова інтерфейсу, тема (темна за замовчуванням), трей, логи (розмір/кількість), ліміти
за замовчуванням для нових ігор, allowlist інтерпретаторів, плагіни адаптерів (увімкнути/вимкнути з
попередженням), «Про програму», перевірка компонентів.

## 8.4. Неблокуюча робота

* HTTP-запити — `QNetworkAccessManager` (асинхронно, сигнали Qt).
* Події — `QWebSocket` до `/admin/v1/events`, автоматичне перепідключення.
* Оновлення UI пакуються (не частіше 10 разів/с) — потік логів не «заморожує» вікно.
* Довгі операції (Start, Stop, бекап) показують індикатор на картці і блокують лише кнопки цієї гри.

## 8.5. Перший запуск

1. Перевірка компонентів: доступ до каталогу даних, БД, вільні порти, наявність `cloudflared` (необов'язково).
2. Короткий «майстер»: назва сервера, режим мережі (за замовчуванням Local), пояснення режимів.
3. Dashboard. Жоден сервер не запущено.

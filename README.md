# HOME GAME SERVER (HGS)

Домашня ігрова серверна платформа для Windows: одне спільне ядро, окремі адаптери для кожної гри,
підключення друзів через інтернет, керування з графічної програми. Нульовий бюджет.

### Що вже працює (Етап 2)

* Програма з темним інтерфейсом: **Dashboard**, **Games**, **Logs**. Ядро працює окремим процесом —
  інтерфейс не зависає, а якщо ядро впаде, з'явиться банер з кнопкою «Перезапустити ядро».
* Додавання гри з папки з `hgs-game.json`, кнопки Start / Stop / Restart / Settings / Logs / Players /
  Status / Invite / Видалити. Підтвердження зупинки, якщо на сервері є гравці.
* Серверне ядро: Gateway (WebSocket) для гравців, Admin API лише на `127.0.0.1`, SQLite, журнали,
  Event Bus, кімнати, гравці, коди запрошень, моніторинг CPU/RAM/мережі.
* HTML-адаптер у режимі `relay`: пересилання подій між гравцями кімнати та спільний стан кімнати.
* Захист: токени лише у вигляді хешів, блокування підбору кодів, ліміти розміру/частоти/глибини
  повідомлень, захист від повторів (`seq`), список дозволених Origin, ліміт з'єднань з IP, журнал безпеки.
* Ізоляція: кімнати й ігри не бачать подій одна одної; помилка або «падіння» однієї гри не зупиняє ядро
  та інші ігри; обмеження автоперезапусків (3 за 10 хв, далі — стан «Помилка»).

### Етап 3

* **JavaScript SDK** [`sdk/js/hgs.js`](sdk/js/README.md): вхід, кімнати, події, автоматичне перепідключення
  з поверненням у кімнату, перевірка аргументів, збереження токена гравця.
* **Серверна логіка ігор** (режим `logic`) на Python: клас на основі `hgs_sdk.GameLogic`, працює в
  **окремому процесі** для кожної гри. На Windows процес гри — у Job Object (обмеження пам'яті; якщо HGS
  аварійно завершиться, Windows сама закриє процеси ігор). Завислий процес гри виявляється і перезапускається.
* **Збереження стану гри**: при зупинці, періодично і відновлення при наступному запуску.
* **Демо-гра** [`examples/demo-arena`](examples/demo-arena/README.md) у двох варіантах (relay і logic).
* Інструкція [«Як підключити нову гру»](docs/guides/add-new-game.md).

### Етап 4

* Сторінка **Network**: режими Local / LAN / Tunnel / Direct, перемикання без перезапуску HGS.
* **Cloudflare Tunnel**: швидкий (без акаунта) і постійний (токен зберігається зашифрованим, не потрапляє в командний
  рядок); нагляд і перезапуск cloudflared; завантаження cloudflared з перевіркою SHA-256.
* **Direct** з TLS (`wss://`), оновлення IP через DuckDNS.
* Перевірка доступності ззовні, публічна IP, підказки про CGNAT, **посилання-запрошення** для друзів.
* Вхід: коди запрошень, **пароль гри**, **акаунти**; вхід без пароля вимикається, коли сервер доступний з інтернету.
* **Повернення в гру після обриву зв'язку** протягом 30 с (одноразові токени повернення, повторне використання
  блокується і пишеться в журнал безпеки); бан і відкликання токенів.
* Інструкція: [docs/guides/internet-access.md](docs/guides/internet-access.md).

Що перевірено лише частково: справжній тунель Cloudflare, завантаження cloudflared і DuckDNS не можна запустити в
середовищі розробки (немає доступу до цих сервісів). Логіка нагляду за тунелем перевірена з імітацією cloudflared;
фінальна перевірка — на вашому ПК (крок 3 в інструкції).

### Етап 5

* **Python Adapter**: режим `worker` (логіка на `hgs_sdk.GameLogic` у **власному venv гри** — без встановлення
  додаткових пакетів) і `standalone` (наявний Python-сервер зі своїм портом: запуск, зупинка, логи, ресурси,
  падіння; гравці проходять через проксі HGS з його лімітами і, за бажанням, входом HGS).
* **Адаптер `process`** для інших мов + приклад на Node.js; [інструкція](docs/guides/write-adapter.md).
* Програми поза папкою гри запускаються лише після дозволу в GUI.
* Гру без `hgs-game.json` можна описати у формі — опис зберігається в HGS, папка гри не змінюється.
  Налаштування гри редагуються в GUI з перевіркою.
* Приклади: [examples/](examples/README.md).

Ще немає: сторінок Players/Rooms/Settings (Етап 6), `.exe` (Етап 8).

## Запуск (для розробки)

Потрібен Python 3.12 або новіший.

```bash
python -m venv .venv
```

```bash
.venv\Scripts\activate
```

```bash
pip install -r requirements-dev.txt
pip install -e . --no-deps
```

```bash
python -m hgs
```

Дані HGS зберігаються в `%LOCALAPPDATA%\HGS` (налаштування, база, логи).
Ядро без GUI: `python -m hgs --core` (друкує одноразовий admin-токен).

## Тести

```bash
python -m pytest -q
```

Браузерним тестам потрібен Chromium: `python -m playwright install chromium` (без нього вони пропускаються).

GitHub Actions запускає тести на Windows і Linux для Python 3.12 та 3.13
(`.github/workflows/tests.yml`).

## Мінімальний `hgs-game.json`

```json
{
  "id": "my-game",
  "name": "My Game",
  "adapter": "html",
  "backend": { "mode": "relay" },
  "auth": { "mode": "invite" },
  "client": { "allowed_origins": ["https://YOUR-NAME.github.io"] }
}
```

Повний формат — [docs/architecture/07-config-and-data.md](docs/architecture/07-config-and-data.md).
